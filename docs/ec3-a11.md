# Reflexión EC3 F2 A11

**1. ¿Qué parte de la aplicación se reemplaza con dobles en `api.test.ts` y qué parte sigue siendo real?**

Se simula la capa de acceso a datos para no depender de MongoDB durante las pruebas. La aplicación Express, sus rutas, controladores, middlewares y validaciones siguen participando en las solicitudes de prueba.

**2. ¿Por qué una suite aprobada no demuestra que MongoDB Atlas esté configurado correctamente?**

Porque las pruebas automatizadas utilizan dobles y no necesariamente establecen una conexión real con Atlas. La conexión debe comprobarse mediante la ejecución de la aplicación y operaciones reales sobre la base de datos.

**3. ¿Qué diferencia existe entre OpenAPI y Swagger UI?**

OpenAPI es la especificación que describe los endpoints, parámetros, respuestas y esquemas de la API. Swagger UI es la interfaz que permite consultar esa documentación e interactuar con los endpoints.

**4. ¿Por qué `GET /api/auth/me` obtiene el id desde el token y no desde params o body?**

Porque el token identifica al usuario autenticado. Obtener el id de una entrada controlada por el cliente permitiría intentar consultar la identidad de otro usuario.

**5. ¿Por qué `authRateLimiter` ya no se monta en todo `authRouter`?**

Porque limitar todas las rutas de autenticación afectaría operaciones que no necesitan la misma restricción. Es mejor aplicar el límite específicamente a las rutas sensibles, como el inicio de sesión y el registro.

**6. ¿Qué diferencia hay entre un error 401 y uno 403 en el cliente?**

El 401 indica que falta una autenticación válida. El 403 indica que el usuario está autenticado, pero no tiene permisos para realizar la operación.

**7. ¿Por qué Postman puede funcionar aunque el navegador informe CORS?**

Porque Postman no aplica las restricciones CORS de los navegadores. Por eso una solicitud puede funcionar en Postman y ser bloqueada cuando se realiza desde React.

**8. ¿Qué riesgo conserva `sessionStorage` y por qué se usa solo como solución didáctica?**

Un ataque XSS podría acceder al token almacenado en `sessionStorage`. Se utiliza como solución didáctica por su sencillez, pero en producción se deben evaluar mecanismos de autenticación más seguros, como cookies HttpOnly, Secure y SameSite.

**9. ¿Qué contrato comparten `openapi.ts`, `types.ts` y las respuestas reales?**

Comparten la estructura de los datos de la API: modelos, propiedades, parámetros y formatos de respuesta. Mantenerlos alineados permite que la documentación, los tipos del cliente y el backend representen el mismo contrato.

**10. ¿Qué prueba agregarías primero antes de desplegar la actividad 12 y por qué?**

Agregaría una prueba de integración para crear una tarea desde React. Comprobaría que envía el token y el título correctamente, recibe HTTP 201, actualiza la lista sin recargar la página y conserva la tarea después de consultar nuevamente la API.
